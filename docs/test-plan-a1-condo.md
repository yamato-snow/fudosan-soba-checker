# 画面テスト項目書 — Phase A-1 区分マンション対応

- 対象: `feat/a1-condo-support`（区分マンションを売買判定の対象種別に追加）
- 目的: **自動テスト（72件）が届かない「画面で見たときの正しさ」**を人が確認する
- 前提: `data/soba.db` に区分490件が取込済み（`python -m app.workers.ingest` 実行済み）

## 起動

```bash
.venv/bin/python -m uvicorn app.main:app --port 8811 --reload
```

ブラウザで `http://127.0.0.1:8811/` を開く。

## テストデータの用意（地区コードを自分で引く）

実在の地区コードはリポジトリに書かないので、手元の DB から引く。

```bash
.venv/bin/python -c "import sqlite3;c=sqlite3.connect('data/soba.db');[print(*r) for r in c.execute(\"select district_code, district_name, count(*), round(min(area)), round(max(area)), min(building_year), max(building_year) from transactions where land_type='中古マンション等' group by district_code order by count(*) desc limit 5\")]"
```

出力の見方と、以下の項目書で使う記号:

| 記号 | 意味 | 選び方 |
|---|---|---|
| **【地区A】** | 区分が潤沢な地区 | 上のコマンドの1行目（件数最多。50件超あるはず） |
| **【地区B】** | 区分が1件しかない地区 | 下のコマンドで引く |
| **【面積A】** | 【地区A】の区分の代表的な専有面積 | 上のコマンドの min〜max の中間（例: 75） |
| **【築年A】** | 【地区A】の区分の代表的な築年 | 上のコマンドの min〜max の中間（例: 2000） |

```bash
.venv/bin/python -c "import sqlite3;c=sqlite3.connect('data/soba.db');[print(*r) for r in c.execute(\"select district_code, district_name from transactions where land_type='中古マンション等' group by district_code having count(*)=1 limit 3\")]"
```

## 不合格だったときの見どころ

| 症状 | 疑うところ |
|---|---|
| B-1 で「延床面積が必要です」 | `valuation.unit_price_for_target()` の `TYPE_CONDO` 分岐が抜けて戸建側に落ちている |
| B-1 で判定不能・事例0件 | `districts.build_case_query()` の延床フィルタが区分にも効いている（区分は `TotalFloorArea` が全件空なので必ず0件になる） |
| C-4 の延床列に数字が出る | 取込側 `reinfolib.normalize()` の種別判定がずれている |
| C-5 の築年がバラバラ | `build_case_query()` の築年フィルタが `TYPE_HOUSE` のみに戻っている |
| D-2 に「土地面積」と出る | `Criteria.area_label` が `EXPANSION_STAGES_CONDO` に設定されていない |
| A-1 に区分が出ない | `constants.TARGET_TYPES` / `TYPE_LABELS` に `TYPE_CONDO` が入っていない |
