# 設計メモ

このツールが「なぜこの作りなのか」を残す。判定ロジックは README の「判定の読み方」が仕様、
ここはその**根拠**（何を試して、何が駄目で、何を選んだか）。

## 解こうとしている問題

不動産の掲載価格を見ても、それが高いのか安いのか分からない。近傍の実取引と比べたい。
国交省の不動産情報ライブラリ（reinfolib）が実取引データを公開しているので、
これを取り込んで「対象物件の㎡単価が、似た事例の分布のどこにいるか」を出す。

制約として最初に決めたこと:

- **推定モデルを作らない**。データ量が小さく、当たっているのか検証できないものを信じない
- **分布をそのまま見せる**。中央値・四分位・使った件数を必ず出し、条件を緩めたなら緩めたと書く
- **判定できないときは判定できないと言う**。無理に数字を出さない

## Phase 0: 座標での近傍抽出は使えなかった

最初は「自分の位置から半径 N km」で近傍を取る設計だった。XPT001（地図タイルAPI）で
実データを取って確認したところ、**返ってくる座標が数km級のクラスタ点**で、
個別取引の位置ではなかった。半径での絞り込みは成立しない。

→ **XIT001（市区町村コード指定）＋「地区リング」方式**へ設計変更した。
距離の代わりに行政区画の入れ子で近さを定義する:

| リング | 範囲 |
|---|---|
| Ring0 | 同一地区（対象物件の DistrictCode） |
| Ring1 | 近隣地区（生活圏。手動設定 or 地価類似で自動推定） |
| Ring2 | 基準市全域（`TARGET_CITIES` の先頭） |
| Ring3 | 対象市全域（`TARGET_CITIES` すべて） |

「動かしてから決める」ためのプローブが `scripts/phase0_probe.py`（記録として残置）。

## データの扱い

- API の `UnitPrice` は使わず、**㎡単価は自前計算**（土地=価格÷土地面積 / 戸建=価格÷延床面積）
- レコードに一意IDが無いので、内容ハッシュ（時期・地区・種別・価格・面積・築年）を
  UNIQUE キーにして**冪等 upsert**。取込バッチは何度流しても増えない
- API は 1req/秒スロットル＋指数バックオフで叩く

## 判定ロジック（Lv1）

事例の㎡単価の**中央値**を相場とし、対象物件との乖離%を主表示。同じ標本の四分位で
3段バンド（Q1未満=割安 / Q1〜Q3=適正 / Q3超=割高）を補助表示する。
事例が5件に満たなければ抽出条件を段階的に緩め、緩めたぶん信頼度を下げる。

回帰やスコアリングを載せていないのは、**1地区あたりの取引が中央値3件しかない**ため。
この密度では係数が安定せず、精度が上がったかどうかも検証できない。

## 改善: 中古戸建の判定が「緩すぎて無害化」していた問題

実データで検証したところ、中古戸建の判定は 0件ではなく**何を入れても「適正」に落ちる**状態だった。
原因は3つあり、それぞれに対処した。

### 1. 比べる軸と絞る軸がズレていた（本丸）

主指標は**延床単価**なのに、事例の絞り込みは**土地面積±30%のみで延床は無条件**だった。
結果、延床40㎡と180㎡が同じ母集団に入り、㎡単価が 33,000〜900,000円/㎡ まで暴れていた
（延床が小さいほど土地値が薄い延床に乗るので単価が跳ね上がる）。

→ **戸建は延床でも絞る**。土地の判定が相対的に当たっていたのは、絞る軸（土地面積）と
比べる軸（土地㎡単価）が一致していたからで、戸建だけこの一致が崩れていた。

拡張段階は種別ごとに分ける。延床は **±50% を下限として撤廃しない**
（撤廃すると今回直した壊れ方に戻る。±50%でも足りないなら「判定できない」と返す方が誠実）。

| 段 | ring | 築年 | 土地面積 | 延床 |
|---|---|---|---|---|
| 1 | 1 | ±5 | ±30% | ±30% |
| 2 | 2 | ±5 | ±30% | ±30% |
| 3 | 3 | ±5 | ±30% | ±30% |
| 4 | 3 | ±10 | ±30% | ±30% |
| 5 | 3 | ±10 | ±30% | ±50% |
| 6 | 3 | 無制限 | ±30% | ±50% |
| 7 | 3 | 無制限 | ±50% | ±50% |

リング拡大を条件緩和より先に置くのは、**似ていない事例で件数を稼ぐより、
範囲を広げて似た事例を探す方が正しい**から。

### 2. 「古家付き土地」相当の外れ値が分布の裾を伸ばしていた

延床45㎡・150万円のような、実質「古家付き土地」の取引が Q1〜Q3 を押し広げ、
バンドが機能しなくなっていた（Q3/Q1 が 2.2倍）。

「古家＝延床◯㎡未満・築◯年超」のような**意味的な除外ルールは作らなかった**。
掲載情報なしに古家か否かは判別できず、恣意的な閾値が新しい歪みになるため。
代わりに統計的に処理する:

- 第1防壁 = 上の延床フィルタ（延床45㎡は105㎡ターゲットの±50%にも入らない）
- 第2防壁 = **IQR トリム**。`[Q1−1.5×IQR, Q3+1.5×IQR]` の外を除外して中央値・四分位を再計算。
  標本が6件未満のときは適用しない（四分位フェンス自体が不安定なため）
- **5件の閾値判定はトリム後の件数**で行う（「使える事例5件」を保証する）。除外件数は必ず表示する

### 3. Ring1 が死んでいた

近隣地区は手動設定（`NEIGHBOR_DISTRICTS`）前提だったが、未設定だと **Ring1 = Ring0** になり、
同一地区の次がいきなり市全域だった。リングの刻みが実質2段しかない。

→ 未設定時は **同一市内で宅地(土地)㎡単価の中央値が対象地区の±25%以内**（双方3件以上）の地区を
Ring1 として自動推定する。座標が使えない環境で「近い」の実用的な代理は「土地の値段水準が近い」であり、
取込済みデータだけで計算できる。手動設定があれば**常にそちらが勝つ**（生活圏の定義は人間の方が正しい）。

### 4. ばらつきが大きいままの「適正」を信頼度に反映する

トリム後でも標本が散らばっているなら、バンド判定の意味は薄い。
最終標本の **Q3/Q1 > 1.8** のとき信頼度を1段下げ（A→B→C）、「ばらつき大」を表示する。

## 効果測定

実データ約2,300件に対し、同一標本で改善前後を比較した（各種別150件を等間隔サンプリング）。

**あるケース（土地180㎡・延床105㎡・築2001年・2,500万円）**

| 指標 | 改善前 | 改善後 |
|---|---|---|
| 事例の延床レンジ | 40〜180㎡ | 85〜135㎡ |
| Q3/Q1 | 2.22倍 | 1.09倍 |
| 中央値比 / バンド | +13.6% / 適正 | +74.0% / 割高 |
| 信頼度 / 最終リング | C / 市全域 | A / 近隣地区 |

無害化していた「適正」が「割高（+74%）」に反転した。

**疑似ターゲット計測（各150件）**

| 指標 | 土地 | 中古戸建 |
|---|---|---|
| 信頼度A | 28.7% → 57.3% | 15.3% → 24.0% |
| 市全域以上まで拡大 | 67.3% → 28.7% | 78.7% → 72.0% |
| Q3/Q1 の中央値 | 1.66 → 1.52倍 | 1.58 → 1.53倍 |

戸建のリング拡大率の改善が小幅なのは、延床フィルタが母集団を正しく削るぶん拡大が起きやすくなるため。
**副作用ではなく設計どおりの挙動**で、信頼度Aは 15.3%→24.0% と改善している。

## 意図的に作っていないもの

- ヘドニック回帰・機械学習（データ量が足りず、精度を検証できない）
- 掲載サイトのスクレイピング、レインズ連携
- 座標・ポリゴンによる地理的な近傍判定（Phase 0 で不可能と確定）
- 認証・マルチユーザー・PostgreSQL 移行（ローカル単独利用のため不要）
